Case Study · n8n Automation

Maintenance Request Automation

A workflow designed to process maintenance requests, avoid re-processing completed records, classify requests by severity, update the source record and notify the appropriate maintenance team.

01 — Business Problem

Maintenance requests can become difficult to track when the same request must be checked, categorized and routed manually. The workflow separates the decision logic from the communication step so each request follows a predictable path.

02 — Workflow Architecture

Manual TriggerStart workflow
Get Requests DataRead maintenance records from Google Sheets
↓
If Status is BlankIF node
Process only unhandled requestsPrevents re-processing records with an existing status
↓
Check SeverityIF node
Severity = High?High requests follow the urgent branch; others follow the normal branch
↓
Update RecordGoogle Sheets
Status = Urgent / NormalSource data is updated before notification
↓
Send EmailGmail
Route to responsible teamUrgent requests → CM team; normal requests → PM team

03 — Input Data

EquipmentEquipment or asset associated with the request.
LocationFacility or location where the issue was reported.
ProblemDescription of the reported maintenance problem.
SeverityUsed by the routing rule to identify high-priority requests.

04 — Core Business Logic

IF Status is blank └── continue processing IF Severity == "High" ├── Update Status = "Urgent" └── Send urgent notification ELSE ├── Update Status = "Normal" └── Send normal maintenance notification

05 — Technologies

n8nGoogle SheetsGmail IF NodesExpressionsJSON

06 — Engineering Value

  • Turns a repetitive routing task into a repeatable workflow.
  • Separates business rules from notification actions.
  • Updates the source record so the request has an explicit processing status.
  • Creates a foundation that can later be extended with webhooks, SLA timers, escalation rules, databases or AI classification.
This portfolio example intentionally uses a simplified maintenance process. Production implementations should also include error handling, duplicate protection, authentication/credential security, logging and escalation rules.
